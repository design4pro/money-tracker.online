# PROCEDURE

1. **Redundancy.** Search the codebase for an existing implementation of the requested behaviour by domain concept, not by the issue's wording. Note where you looked. Found → verdict `redundant`.
2. **Prior rejection.** If `.out-of-scope/*.md` exists, read it; a matching record → verdict `redundant`.
3. **Verify the claim at HEAD.**
   - `type: bug`: reproduce it. Prefer a temporary vitest case at the seam the issue names (`pnpm test -- <file>`); otherwise run the exact command or steps the body gives. Quote the failing assertion or output.
   - `type: maintenance`: run the command that proves the debt — `pnpm db:generate`, `pnpm generate-routes && git diff --exit-code src/routeTree.gen.ts`, a grep proving a guard is missing, a test that passes when it should fail. Quote the output.

   Verdict: `confirmed` (with the proof), `refuted` (HEAD does not exhibit it — quote why), or `insufficient` (cannot be reproduced from what is written — name the exact missing detail).

   Never commit, never push, never run `--update-snapshots`, never edit `e2e/__screenshots__`. Delete any temporary test you wrote; the workspace is thrown away.

4. **Fix direction.** A brief commits to one direction. Choose only when SPEC, the ADRs and the code make the choice mechanical, and write down what settles it. When the body lists alternatives with different user-visible or contract consequences and nothing in the docs decides between them, it is a product or API decision → verdict `needs-human`.
