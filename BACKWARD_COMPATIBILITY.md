# Backward compatibility

The surfaces of money-tracker.online that something outside the current deploy depends on: a row
already written, a Worker still running during the migrate-then-deploy window, a message in flight,
a URL in somebody's inbox. A change to one of them without its required path is a blocker in review
(`CODE_REVIEW.md`); an implementing skill warns before making one.

The general rule is `docs/SPEC.md` §6.1: **migrations are additive, and a removal or a narrowing is
two releases, not one.** Add the new thing, move every reader and writer, and only then remove the
old one in a later release.

| Surface                    | Where it lives                                                                                                                                                            | What breaks it                                                                                                          | Required path                                                                                                                                                                                                                                                   |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1 schema                  | `src/server/db/schema.ts`, `src/server/db/auth-schema.ts`, `drizzle/` (generated)                                                                                         | Dropping, renaming or narrowing a column or table; a constraint existing rows violate; a nullable column made required  | Additive migration via `pnpm db:generate`; stop writing the old shape; drop it in a later release. Every product table keeps `organization_id` first in each composite index (SPEC §5.2).                                                                       |
| Stored money               | `amount_minor`, `ref_amount_minor`, `rate_e10`, `currencies.digits`, `account_balances`                                                                                   | Changing a scale, recomputing a historical ref amount, reinterpreting a stored value, writing a balance directly        | Never in place. A new column with a backfill job on `TASKS`; the arithmetic is `docs/MONEY.md` and is cited, not restated.                                                                                                                                      |
| Tenant scope               | `src/server/repos/scope.ts`, `src/server/repos/base.ts`                                                                                                                   | A repository function that no longer takes a `TenantScope` first, or a predicate a caller can remove                    | ADR 0002. There is no path around it; the change is rejected.                                                                                                                                                                                                   |
| Auth and sessions          | `/api/auth/*` (Better Auth), the KV session store, `BETTER_AUTH_SECRET`, `APP_URL`                                                                                        | Rotating the secret without a plan, changing the session shape, renaming a secret                                       | ADR 0011. Rotation invalidates every session and is announced; a renamed secret is added, set in every environment, then the old name removed.                                                                                                                  |
| Billing                    | `/api/webhooks/polar`, `/api/billing/{checkout,portal,return}`, `billing_events`, the plan catalogue and resolver in `src/lib/plans.ts`                                   | A webhook that stops verifying or acknowledging; a plan or quota published in one place and enforced in another         | ADR 0012. A webhook shape change keeps the old parser one release; a catalogue change lands in the catalogue and the resolver in the same PR (SPEC §8).                                                                                                         |
| Queue messages             | `src/server/queue/messages.ts` (`taskMessageSchema`), `src/server/queue/handlers/`                                                                                        | Changing a message shape while messages of the old shape are in flight or in the dead-letter queue                      | New `kind`, old handler kept for one release; unknown bodies are reported and acknowledged, never retried into the DLQ. A known kind with no handler installed is retried into the DLQ, never acknowledged; a producer must not ship before its consumer.       |
| Durable Objects            | `LEDGER` in `wrangler.jsonc`, `src/server/do/`                                                                                                                            | Renaming or deleting a class; editing an existing entry of the `migrations` list                                        | The `migrations` list is append-only (ADR 0013 shows the `deleted_classes` step).                                                                                                                                                                               |
| Bindings and configuration | `wrangler.jsonc` binding names, `.dev.vars.example`, `VITE_*` public values                                                                                               | Renaming a binding, a secret or a public variable                                                                       | Add the new name, migrate every environment, remove the old name in a later release. `.dev.vars.example` documents the current set.                                                                                                                             |
| Public URLs                | Route files under `src/routes/`, `/api/health`, `/api/files/$id`, `/invite/$invitationId`, `/unsubscribe` and `/api/unsubscribe` with their `v1.` token, email deep links | Changing a URL a person may have bookmarked or an email already links to; changing what a `v1.` unsubscribe token means | Keep a redirect from the old path for as long as an email can be unread; invite links stay valid until their own expiry. The `v1.` unsubscribe token shape is permanent: a new shape is `v2.`, and `v1.` keeps verifying until the last `v1.` link has expired. |
| Message catalogue          | `src/lib/i18n/messages/{en,pl}.ts`; notification rows and email envelopes store keys and parameters                                                                       | Removing or renaming a key that a stored row references; renaming a placeholder                                         | Keep the old key until no stored row uses it; a placeholder rename is a new key. Both locales change in the same commit.                                                                                                                                        |
| Import formats             | `src/server/import/` (CSV, OFX, QIF parsers), import presets and mappings stored per workspace                                                                            | A parser that rejects a file it used to accept; a preset shape stored rows no longer match                              | Widen before narrowing; migrate stored presets with an additive change.                                                                                                                                                                                         |
| Seed and fixtures          | `scripts/seed/seed.mjs`, `scripts/seed/verify.mjs`, `e2e/baseline-day.ts`                                                                                                 | A fixture count or the anchored day changed without the suites and the audit following                                  | Update `verify.mjs` and every dependent suite in the same PR; the day is moved as one deliberate change.                                                                                                                                                        |
| Package scripts            | `package.json` scripts that `.github/workflows/ci.yml`, `.ai/agentic.config.json` and `SDLC.md` name                                                                      | Renaming or removing one                                                                                                | Change all four in one PR.                                                                                                                                                                                                                                      |
| Accessibility claim        | `docs/ACCESSIBILITY.md`                                                                                                                                                   | Any copy, comment or commit claiming more than it states                                                                | The claim changes only through that document and an ADR (ADR 0009).                                                                                                                                                                                             |

Out of scope permanently, and therefore never a compatibility question: bank connectors,
aggregators and credential capture (ADR 0008).
