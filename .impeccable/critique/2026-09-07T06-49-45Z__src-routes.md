## Design Specificity Verdict

The landing is authored; the signed-in app is half-authored, and the seam between them is the product's own thesis.

Where the world holds: `/` (ruled paper, hand h1 on the rules, real LedgerPreview with balance-after spine, SETTLED mark, pencil planned line, frozen EUR→PLN, hatched over-budget meter, one violet stamp), auth, the shell (rail on surface-sunken, 1px border-panel current frame, solid bottom bar, verified two-ring focus), the dashboard's three-line dl summary, the budgets list, the four amount tones, and the dark set.

Where it falls back to SaaS-dashboard form:

1. The ledger is a data table, not the passbook. /transactions and /accounts/$accountId: checkbox/date/description/category/account/amount/⋯ with day-total bands. No balance-after column anywhere in the product's own ledger.
2. Dashboard is a card grid (widget-grid.tsx + widget-frame.tsx wrap every panel in Card); net-worth-widget.tsx:80 is an xl hero figure under a small caption in a ~40% empty card.
3. Accounts overview is eyebrow + hero tile + icon tiles (accounts/overview-card.tsx:70-82; initials squares on rows; hand headings italic uppercase).
4. Violet on non-actions by token design: info shares brand, so every Badge tone="info" is a stamp (settings/index.tsx:249, recurring/series-card.tsx:112, transaction-row.tsx:206, category-tree.tsx:172, account-badges.tsx:61); template picker is Card variant="brand".
5. Pills ship: filter-bar.tsx:210 and :661 use Button shape="pill".
6. Record names in the hand (account/budget/series via text-subtitle) while the same names are typed in the ledger.

## Overall Impression

The landing makes a promise the product is built to keep and the arithmetic layer keeps it. Then the signed-in screens stop speaking passbook and start speaking dashboard: cards, tiles, a table, a stamp on every status. Biggest opportunity: put the balance-after column and the typed line into /transactions and the per-account view.

## What's Working

- The landing's proof is the product: LedgerPreview and BudgetStates are the real components with static props; U+2212, tabular figures, frozen ref_amount_minor (€27.40 → zł 118.42) and the four-channel over-budget encoding are demonstrated, not claimed.
- Money is spoken as well as drawn everywhere: aria-hidden drawing + sr-only sentence per amount; both charts carry a data table; direction is sign + weight + glyph + word before colour.
- Shell geometry is disciplined: one element clears each fixed edge, scroll-padding matches, solid bottom bar above the safe area, current destination marked three ways, two-ring focus measured on the rail.
